# Android Navigation SDK integration — staging design

Status: integration preparation only; no SDK enabled or billable requests yet.

The Android project is generated by Capacitor 7 in CI and is gitignored. Native changes must be reproducibly applied after cap add android, rather than editing generated files only.

- Use an opt-in native build variant and a separate staging web origin; the current capacitor.config.json loads Production.
- Verify SDK/AGP/Gradle compatibility in CI before enabling the dependency. SDK 7.3–7.6 requires AGP 8.10.0 / Gradle 8.11.1; SDK 8 requires AGP 9.0.1 / Gradle 9.1.0. Current generated versions must be checked.
- Register a Capacitor plugin with capability detection, validated destination coordinates, single active navigation session, cancellation and explicit error results. Restrict trusted web origins.
- Use native Google guidance UI, preserve attribution and required terms and notices. Do not overlay or obscure safety controls.
- Keep existing web navigation as fallback; never start both location tracking sessions simultaneously.
- API key must be supplied outside source control, restricted to the Android application ID and signing certificate and Navigation SDK API. No billing activation or real requests before owner approval.
- Acceptance: clean no-key build, opt-in SDK build, denied permissions/terms, repeated start/stop, route deviation, background/foreground, return to parking, physical Android test.
- No changes to parking or staff systems, no merge to main.
